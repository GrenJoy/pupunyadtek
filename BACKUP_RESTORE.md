# 💾 Резервное копирование и восстановление проекта

## ⚠️ ВАЖНО: Файлы сессии НЕ в Git!

Файлы `.session` и `.env` **НЕ попадают в Git репозиторий** (они в `.gitignore`).

Это означает:
- ✅ **Безопасность**: Никто не сможет скачать ваши секреты из GitHub
- ⚠️ **Потеря данных**: Если удалите проект локально, файлы сессии будут потеряны

## 📋 Что нужно сохранить перед удалением проекта

### 1. Сохраните `TELEGRAM_SESSION_STRING`

**Способ 1: Из файла `.env`**
```bash
# Откройте .env файл и скопируйте строку:
TELEGRAM_SESSION_STRING=ваша_строка_сессии_здесь
```

**Способ 2: Сгенерируйте заново (если потеряли)**
```bash
python create_session.py
```
Или используйте расширенную версию:
```bash
python generate_session.py
```

**Способ 3: Из переменных окружения на Render**
- Зайдите в Render Dashboard → ваш сервис → Environment
- Скопируйте значение `TELEGRAM_SESSION_STRING`

### 2. Сохраните другие секреты из `.env`

Создайте файл `secrets_backup.txt` (НЕ коммитьте его в Git!) со следующим содержимым:

```
TELEGRAM_BOT_TOKEN=ваш_токен
GEMINI_API_KEY=ваш_ключ
TELEGRAM_API_ID=ваш_id
TELEGRAM_API_HASH=ваш_hash
TELEGRAM_SESSION_STRING=ваша_сессия
```

**⚠️ Храните этот файл в безопасном месте (не в Git, не в облаке без шифрования!)**

### 3. Сохраните базу данных (если используете SQLite локально)

```bash
# Скопируйте файл bot.db в безопасное место
cp bot.db backup_bot.db
```

**Примечание**: На Render используется PostgreSQL, данные там сохраняются автоматически.

## 🔄 Восстановление проекта после удаления

### Шаг 1: Клонируйте репозиторий

```bash
git clone <ваш-репозиторий-url>
cd power-outage-schedule-bot
```

### Шаг 2: Восстановите `.env` файл

**Вариант A: Из бэкапа**
```bash
# Скопируйте сохранённый secrets_backup.txt в .env
cp secrets_backup.txt .env
```

**Вариант B: Создайте вручную**
```bash
# Создайте .env файл
touch .env
```

Затем добавьте в него:
```env
TELEGRAM_BOT_TOKEN=ваш_токен
GEMINI_API_KEY=ваш_ключ
TELEGRAM_API_ID=ваш_id
TELEGRAM_API_HASH=ваш_hash
TELEGRAM_SESSION_STRING=ваша_сессия
```

### Шаг 3: Установите зависимости

```bash
pip install -r requirements.txt
```

### Шаг 4: Проверьте работу

```bash
python bot.py
```

- ❌ Файлы `.session` - **НЕ в Git**
- ❌ Файл `.env` - **НЕ в Git**

- ✅ Исходный код (`.py` файлы)
- ✅ Конфигурационные файлы (`requirements.txt`, `render.yaml`)
- ✅ Документация (`README.md`, `SECURITY.md`)
- ✅ Скрипты (`generate_session.py` - но он требует секреты из `.env`)

### 🎯 Ответы на ваши вопросы:

**Q: Если я удалю проект локально и скачаю снова, будут ли файлы сессии?**
A: **НЕТ**. Файлы сессии не в Git, их нужно восстановить из бэкапа или сгенерировать заново.

**Q: Лежат ли файлы сессии в открытом доступе?**
A: **НЕТ**. Файлы `.session` в `.gitignore`, они **НЕ попадают в Git репозиторий**.

**Q: Если я скачаю с GitHub, получу ли я файлы сессии?**
A: **НЕТ**. Даже вы (владелец) не получите файлы сессии при клонировании, потому что они **не были закоммичены** в Git.

**Q: Если кто-то другой скачает репозиторий, получит ли он сессию?**
A: **НЕТ**. Он получит только открытый код, но **НЕ получит**:
- Файлы `.session`
- Файл `.env`
- Ваши секреты

## 💡 Рекомендации по резервному копированию

### 1. Используйте менеджер паролей

Сохраните `TELEGRAM_SESSION_STRING` в менеджере паролей (1Password, Bitwarden, LastPass и т.д.)

### 2. Используйте зашифрованное хранилище

Сохраните `secrets_backup.txt` в зашифрованном архиве или в зашифрованном облачном хранилище.

### 3. На Render всё уже сохранено

Если вы используете Render, все секреты уже хранятся в Environment Variables на сервере. Просто скопируйте их оттуда при восстановлении.

### 4. Создайте приватный Gist (опционально)

Можно создать приватный Gist на GitHub с вашими секретами (но это менее безопасно, чем менеджер паролей).

## 🚨 Что делать, если потеряли сессию?

1. **Сгенерируйте новую сессию:**
   ```bash
   python generate_session.py
   ```

2. **Обновите на Render:**
   - Зайдите в Render Dashboard → ваш сервис → Environment
   - Обновите `TELEGRAM_SESSION_STRING`
   - Перезапустите сервис

3. **Обновите локально:**
   - Добавьте новую сессию в `.env`
   - Перезапустите бота
