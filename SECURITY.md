# 🔒 Безопасность проекта

## ⚠️ КРИТИЧЕСКИ ВАЖНО

Этот проект содержит скрипты для работы с Telegram API, которые требуют секретных ключей и токенов.

## ✅ Что уже защищено

1. **`.gitignore` правильно настроен:**
   - `.env` файлы игнорируются
   - Файлы `.session` игнорируются
   - Файлы `last_message_id*.txt` игнорируются
   - База данных `bot.db` игнорируется

2. **Проверка перед коммитом:**
   ```bash
   git status
   ```
   Убедитесь, что секретные файлы не попадают в коммит!

## 🛡️ Защита ваших секретов

### 1. Локальная разработка

- ✅ Используйте `.env` файл для хранения секретов
- ✅ `.env` уже в `.gitignore` - не будет закоммичен
- ❌ НИКОГДА не коммитьте `.env` файл
- ❌ НИКОГДА не коммитьте файлы `.session`

### 2. Генерация сессии (`create_session.py` или `generate_session.py`)

**Важно понимать:**
- Скрипты требуют `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` из `.env`
- Без этих переменных скрипты **не запустятся**
- Если кто-то клонирует репозиторий, у него **не будет** доступа к вашему `.env`
- `generate_session.py` показывает предупреждения о безопасности

**Доступные скрипты:**
- `create_session.py` - простой скрипт для быстрой генерации
- `generate_session.py` - расширенный скрипт с предупреждениями

**Как это работает:**
1. Кто-то клонирует репозиторий → у него нет `.env` файла
2. Пытается запустить `create_session.py` или `generate_session.py` → получает ошибку
3. Не может сгенерировать сессию без ваших `API_ID` и `API_HASH`

### 3. На сервере (Render)

- ✅ Используйте **Environment Variables** в настройках сервиса
- ✅ НЕ храните секреты в коде
- ✅ `render.yaml` использует `sync: false` для секретов (они не синхронизируются из Git)

## 🚨 Что делать, если случайно закоммитили секреты

1. **Немедленно смените все ключи/токены:**
   - Telegram Bot Token (через @BotFather)
   - Gemini API Key (через Google AI Studio)
   - Telegram API ID/Hash (можно оставить, но лучше пересоздать)
   - Сгенерируйте новую сессию

2. **Удалите секреты из истории Git:**
   ```bash
   # Используйте BFG Repo-Cleaner или git filter-branch
   # Или создайте новый репозиторий без истории
   ```

3. **Проверьте форки:**
   - Убедитесь, что секреты не попали в публичные форки
   - Если попали - попросите владельцев удалить

## ✅ Проверка безопасности

Перед каждым коммитом проверяйте:

```bash
# Проверить, что .env игнорируется
git check-ignore .env

# Проверить, что файлы сессий игнорируются
git check-ignore *.session

# Посмотреть, что будет закоммичено
git status
git diff
```

## 🔍 Дополнительная защита

### API и бекенд

- ✅ `api.py` не содержит секретов - они берутся из переменных окружения
- ✅ Все API ключи загружаются через `os.getenv()` из `.env`
- ✅ На Render все секреты в Environment Variables

### Мониторинг

- ✅ Бот использует только публичные каналы (чтение)
- ✅ Сессия нужна только для чтения каналов, не для управления аккаунтом
- ✅ Но сессия всё равно даёт доступ к аккаунту - храните её безопасно!

## 💡 Рекомендации

1. **Используйте отдельный Telegram аккаунт** для бота (если возможно)
2. **Включите двухфакторную аутентификацию** в Telegram
3. **Регулярно проверяйте** активные сессии в настройках Telegram
4. **Используйте разные API ключи** для разработки и продакшена
5. **Ограничьте доступ** к репозиторию (если возможно, сделайте приватным)

## 📞 Если что-то пошло не так

Если вы подозреваете, что секреты скомпрометированы:

1. Немедленно смените все ключи
2. Отзовите все сессии в настройках Telegram
3. Проверьте логи на подозрительную активность
4. При необходимости - обратитесь в поддержку Telegram
