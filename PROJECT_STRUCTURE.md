# 📁 Структура проекта Power Outage Schedule Bot

Полное описание всех файлов проекта, их назначения и взаимосвязей.

---

## 🎯 Основные компоненты

### 🤖 **bot.py** - Главный файл Telegram бота
**Назначение:** Основной файл, который запускает Telegram бота и обрабатывает все команды пользователей.

**Что делает:**
- Инициализирует Telegram бота через `python-telegram-bot`
- Обрабатывает команды (`/start`, `/help`, `/schedule` и т.д.)
- Управляет городами, людьми, каналами через интерфейс бота
- Позволяет загружать графики вручную
- Показывает графики отключений для пользователей
- Запускает HTTP сервер для пинга (чтобы Render не засыпал)
- Запускает автоматический мониторинг каналов в фоне

**Ключевые функции:**
- `start()` - команда `/start` (главное меню)
- `view_schedule_person()` - просмотр графика для человека
- `add_city()`, `add_person()`, `add_channel()` - управление данными
- `upload_schedule()` - ручная загрузка графика
- `start_monitoring()` - команда `/start_mon` (ручной запуск мониторинга каналов)

**Зависимости:** `database.py`, `gemini_service.py`, `helpers.py`, `channel_fetcher.py`, `channel_monitor.py`

---

### 🗄️ **database.py** - Работа с базой данных
**Назначение:** Управление всеми операциями с базой данных (SQLite или PostgreSQL).

**Что делает:**
- Автоматически определяет тип БД (SQLite для локальной разработки, PostgreSQL для продакшена)
- Создаёт таблицы при первом запуске
- Хранит города, людей, каналы, графики отключений
- Поддерживает графики на "сегодня" и "завтра" отдельно
- Выполняет миграции схемы БД
- Ротация графиков (tomorrow → today) в полночь

**Ключевые классы:**
- `Database` - основной класс для работы с БД
- `City`, `Person`, `Channel` - dataclass модели данных

**Ключевые методы:**
- `get_cities()`, `add_city()`, `delete_city()` - управление городами
- `get_people()`, `add_person()`, `update_person()` - управление людьми
- `save_schedule()` - сохранение графика (today/tomorrow)
- `get_schedule_for_group()` - получение графика для группы
- `get_both_schedules()` - получение обоих графиков (today + tomorrow)
- `rotate_schedules()` - ротация графиков в полночь

**Зависимости:** `sqlite3`, `psycopg` (для PostgreSQL)

---

### 📡 **channel_monitor.py** - Автоматический мониторинг каналов
**Назначение:** Автоматически отслеживает Telegram-каналы и обрабатывает новые посты с графиками.

**Что делает:**
- Подключается к Telegram через Telethon
- Мониторит указанные каналы в реальном времени
- Ищет посты с ключевыми словами (из `constants.py`)
- Скачивает и анализирует фото с графиками
- Обрабатывает альбомы (несколько фото в одном посте)
- Определяет дату графика (сегодня/завтра) через Gemini
- Сохраняет графики в базу данных
- Отправляет уведомления подписчикам об изменениях

**Ключевые классы:**
- `ChannelMonitor` - основной класс мониторинга

**Ключевые методы:**
- `start_monitoring()` - запуск мониторинга
- `stop_monitoring()` - остановка мониторинга
- `process_photo()` - обработка фото с графиком
- `download_and_process_photos()` - обработка альбомов
- `_notify_subscribers_about_changes()` - отправка уведомлений

**Зависимости:** `database.py`, `gemini_service.py`, `helpers.py`, `constants.py`, `telethon`

---

### 🔍 **channel_fetcher.py** - Поиск графиков по запросу
**Назначение:** Поиск и обработка графиков из каналов по запросу пользователя (ручная загрузка).

**Что делает:**
- Ищет последние посты с графиками в указанном канале
- Скачивает фото с графиками
- Обрабатывает альбомы (несколько фото)
- Извлекает дату из текста поста
- Анализирует фото через Gemini
- Возвращает найденные графики для сохранения

**Ключевые функции:**
- `find_and_process_schedule_for_user()` - поиск графика для пользователя
- `get_schedule_photos_from_channel()` - получение фото из канала
- `download_and_process_photo_from_message()` - обработка фото
- `extract_date_from_text()` - извлечение даты из текста

**Зависимости:** `database.py`, `gemini_service.py`, `constants.py`, `telethon`

---

### 🤖 **gemini_service.py** - Интеграция с Gemini AI
**Назначение:** Работа с Google Gemini API для анализа изображений и генерации ответов.

**Что делает:**
- Анализирует фото с графиками отключений
- Извлекает группы и интервалы отключений из изображений
- Определяет, относится ли график к сегодня или завтра
- Генерирует красивые ответы для пользователей на украинском языке
- Проверяет полноту графика

**Ключевые функции:**
- `analyze_schedule_image()` - анализ фото с графиком
- `check_schedule_post_and_date()` - определение даты графика (today/tomorrow)
- `generate_schedule_response()` - генерация красивого ответа для пользователя
- `analyze_schedule_text()` - анализ текста поста
- `is_complete_schedule()` - проверка полноты графика
- `merge_schedules()` - объединение графиков из нескольких фото

**Зависимости:** `google.generativeai`, `PIL` (Pillow)

---

### 🛠️ **helpers.py** - Вспомогательные функции
**Назначение:** Утилиты для работы со временем и статусом графика.

**Что делает:**
- Определяет текущий статус подачи электричества (есть/нет свет)
- Вычисляет время до следующего изменения
- Работает с часовым поясом Киева (Europe/Kyiv)
- Форматирует разницу времени

**Ключевые функции:**
- `get_schedule_status()` - определение статуса (свет есть/нет, следующее изменение)
- `get_kyiv_time()` - получение текущего времени в часовом поясе Киева
- `format_time_diff()` - форматирование разницы времени

**Зависимости:** `datetime`, `zoneinfo` или `pytz`

---

### 📋 **constants.py** - Константы проекта
**Назначение:** Хранение констант и настроек проекта.

**Что содержит:**
- `ELECTRICITY_GROUPS` - список групп электричества (1.1, 1.2, 2.1, ... 6.2)
- `KEYWORDS` - ключевые слова для поиска постов с графиками

**Используется в:** `channel_monitor.py`, `channel_fetcher.py`

---

### 🌐 **api.py** - REST API и веб-интерфейс
**Назначение:** FastAPI приложение для пинга сервера и веб-интерфейса.

**Что делает:**
- Предоставляет REST API для управления данными (города, люди, графики)
- Отвечает на `/health` и `/` для пинга (чтобы Render не засыпал)
- Показывает HTML страницу со статусом бота
- Позволяет загружать графики через API

**Ключевые endpoints:**
- `GET /` - пинг сервера
- `GET /health` - проверка работоспособности
- `GET /status` - HTML страница со статусом
- `GET /api/cities` - список городов
- `POST /api/upload_schedule` - загрузка графика

**Зависимости:** `fastapi`, `database.py`, `gemini_service.py`

## 🔧 Утилиты и скрипты

### 🔐 **create_session.py** - Простой скрипт для создания сессии
**Назначение:** Упрощённый скрипт для генерации Telegram сессии.

**Использование:**
```bash

```

**Что делает:**

- Подключается к Telegram
- Генерирует строку сессии
- Выводит инструкции по добавлению в `.env`

**Отличия от `create_session.py`:**
- Показывает предупреждения о безопасности

## 🔄 Как всё работает вместе

### 1. **Запуск бота** (`bot.py`)
```
bot.py → инициализирует Database
       → запускает Telegram бота
       → запускает HTTP сервер (api.py)
       → запускает ChannelMonitor в фоне
```

### 2. **Мониторинг каналов** (`channel_monitor.py`)
```
ChannelMonitor → подключается к Telegram
               → мониторит каналы
               → находит посты с KEYWORDS
               → скачивает фото
               → анализирует через gemini_service.py
               → сохраняет в database.py
               → отправляет уведомления через bot.py
```

### 3. **Обработка команд** (`bot.py`)
```
Пользователь → команда /schedule
            → bot.py обрабатывает
            → database.py получает график
            → gemini_service.py генерирует ответ
            → bot.py отправляет пользователю
```

### 4. **Ручная загрузка** (`channel_fetcher.py`)
```
Пользователь → команда "Загрузить график"
            → channel_fetcher.py ищет в канале
            → скачивает фото
            → gemini_service.py анализирует
            → database.py сохраняет
```

## 📊 Схема данных

### Таблицы базы данных:

1. **cities** - города
   - `id` (INTEGER PRIMARY KEY)
   - `name` (TEXT)

2. **people** - люди (пользователи бота)
   - `id` (INTEGER PRIMARY KEY)
   - `name` (TEXT)
   - `city_id` (INTEGER, FOREIGN KEY)
   - `group` (TEXT) - группа электричества (1.1, 1.2, ...)

3. **channels** - Telegram каналы для мониторинга
   - `id` (INTEGER PRIMARY KEY)
   - `city_id` (INTEGER, FOREIGN KEY)
   - `channel_username` (TEXT)
   - `last_message_id` (INTEGER)

4. **schedules** - графики отключений
   - `city_id` (INTEGER PRIMARY KEY)
   - `schedule_today` (JSON) - график на сегодня
   - `schedule_tomorrow` (JSON) - график на завтра
   - `schedule_data` (JSON) - устаревшее поле (для совместимости)
   - `updated_at` (TIMESTAMP) - время обновления

5. **subscribers** - подписчики на уведомления
   - `user_id` (INTEGER)
   - `person_id` (INTEGER, FOREIGN KEY)

## 🎯 Основные потоки данных

### Поток 1: Автоматический мониторинг
```
Telegram канал → ChannelMonitor → Gemini API → Database → Уведомления → Пользователи
```

### Поток 2: Ручная загрузка
```
Пользователь → Bot → ChannelFetcher → Gemini API → Database
```

### Поток 3: Просмотр графика
```
Пользователь → Bot → Database → Gemini API (генерация ответа) → Пользователь
```

### Поток 4: Пинг сервера
```
Render → HTTP запрос → API (/health) → Ответ "ok" → Render не засыпает
```
